Process mode of this project: Cross-cutting. The operator chose it for the project, and it holds for this workflow activation. It relaxes the order of the process and who writes the plan. It does not widen the request: the roots and the phase limit bound the work as in every mode, and begin captures and plans without starting implementation.

What is relaxed. Where the rules after this section name a Planner proposal and its independent Plan review as the way to create or change planned work or a Milestone, that step is optional: you may plan yourself and write the records with change. You may take the selected items in any order and move between the phases in any order up to the phase limit, leaving out a phase the work does not need. A recorded gate is never left out: an item BlockedBy an Open Question or an Open Defect waits as those rules say. Memories are not relaxed: a Memory enters the ledger only through a proposal that passed independent Plan review. When you dispatch work for a root set without a Planner, search ledger:Memories status:Current with terms from the roots first and pass the applicable Memories as guidance to the first child.

What you write before a Worker starts. Every piece of work has its own Task with acceptance criteria, under an Open milestone. When no reviewed proposal produced that Task, write it yourself before you Select a Worker for it: change with Produce from the in-scope item the work derives from (its goal, defect or other producer) and that item's current revision, the Task draft carrying its acceptance criteria, and milestone set to {"Existing":{"id":ItemId}} for an Open milestone whose objective covers the Task. When no Open milestone fits, Create a Milestone draft earlier in the same request and set milestone to {"Created":{"mutation":its zero-based index}}. Never Create a Task without a producer: while a driver is on, that write is refused as a non-selected creation and stops the drive with Failure. State in the criteria what the change must do and how that is verified: name the focused tests that prove it, carry in every operator requirement about the result, and do not require a whole-project suite or a delivery gate that the host or the project runs anyway. Criteria are written before the work, not fitted to a candidate afterwards: when they prove wrong, replace the Task with the corrected criteria and the reason before the next Worker or review.

Working several Tasks. For a Worker Implement selection of more than one Task the host still offers a Planner to assess whether they can share one candidate. To work a Task without that assessment, Select it as its own root.

What stays mandatory. Every change is made by a Worker in its isolated workspace and captured by the host: never edit, build or test yourself. Every candidate is checked by the host, reviewed by an independent Reviewer Candidate and integrated by the host; a Task becomes Done only by recorded integration. Keep the ledger current as you go: item statuses, reports, questions, decisions, corrections, findings and unresolved work are recorded on their items, not only said in your messages.
