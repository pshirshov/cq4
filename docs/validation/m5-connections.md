# M5 connection diagnostics and lifecycle

This increment completes the connection portion of the [browser plan](../design/browser-workspace.md). It changes browser transport/presentation and focused fixtures; no generated contract, service, adapter, dispatch or harness behavior changes. The current schema remains `0.1.0`.

## Implemented behavior

- One persistent top-bar indicator derives its state from the connection manager and mirrors it in the tab title. Transport state remains distinct from item synchronization and usage observation freshness.
- Waiting phases carry their actual start and duration: native connection (10 seconds), pong (5 seconds), stale grace (15 seconds) and sampled backoff. The countdown uses that budget, is hidden without a deadline and has an accessible phase/remaining-time label. State changes render immediately; animation is throttled to 100 ms with requestAnimationFrame.
- The expanded view retains controls and keyed connection cards. It shows active/background identity, connection age and first verification, in-flight/sent probes, heartbeat deadline misses, 30/60/300-second RTT min/median/max/count, retry attempts/next wait, last peer close and the timestamped event log. It sits below the top bar and scrolls within the viewport at desktop/narrow widths.
- A heartbeat deadline miss is counted once when its deadline elapses, including a late matching pong before the next timer tick. The percentage denominator is timely responses plus missed deadlines. Outstanding probes and early superseded probes are excluded. This is **not measured network packet loss**. Duplicate/unknown nonces cannot add RTT samples. RTT retention is capped at 512 samples and five minutes per live connection; the UI states that cap. Closed connections are removed; the last peer close and bounded event log remain.
- Pool size remains at most two, pending probes at most three per connection, and event history at most 100. Retry delay is `min(30s, 500ms × 2^attempt) × U[0.5, 1.0)`, with at most twelve attempts before manual retry. This is half-to-full jitter, matching the reference implementation's distribution; it is not full jitter over `[0, cap]`.
- Hidden reconnection is deferred without consuming an attempt, then starts immediately on visibility restoration. Pagehide closes all sockets and publishes SUSPENDED; pageshow starts one attempt and resets the scheduling-gap clock. A scheduling gap exceeding one second rechecks existing sockets; a gap of at least five seconds proactively permits a replacement. Freeze is logged; resume/network events check liveness under the same pool bound. Offline invalidates freshness; it does not establish that all transports have failed.

## Explicit scope and limits

The requested `resilient-ws-ui` patterns are adapted to CQ's generated nonce protocol. RTT uses the locally recorded send time for the matching nonce; a server timestamp is unnecessary for round-trip measurement. The unchanged ZIO server keeps current/previous heartbeat nonces and yields/rechecks before closing an expired session, rather than using Node's setImmediate. Server heartbeat expiry under actual scheduler stalls has not been fault-injected by this browser increment.

Synthetic lifecycle events test handler behavior over actual sockets; they do not prove browser BFCache admission or physical OS sleep scheduling. Browser-clock jumps simulate main-thread scheduling gaps. No continuous heartbeat execution while the page is frozen/hidden is claimed; the UI explicitly describes suspension limits. Actual offline/online recovery is also exercised by the main browser fixture. Firefox/WebKit and assistive-technology user acceptance are not claimed by Chromium/DOM/keyboard checks.

The indicator does not assert data synchronization from a pong. Item snapshot/change replay and stale-cursor resnapshot, usage cursor rewatch and exact persisted mutation retry remain separate application protocols verified by their linked M5 fixtures. Native asset packaging and final human acceptance remain M6 gates.
