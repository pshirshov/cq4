# Intake-to-integration assessment rubric

Assess each assigned task on the exact current workspace base and the supplied CQ evidence. This rubric is evaluation input prepared by the runner, not a user acceptance verdict. The initial user language reply is separate evidence. Do not execute checks in Audit mode; inspect the linked host observations and candidate source, tests and README.

1. **Deliverable.** Compare both task scopes and the complete original word-frequency specification with the Go implementation, automated tests and exact run/test instructions. Verify the original specification survived planning and decomposition. Treat the oracle as evidence for its tested behavior, not proof of every requirement.
2. **Actual choice.** Trace the unanswered checkpoint to the supplied Go reply, its Human-authored Question revision and immutable file/commit citation. Verify the adopted Decision derives from that Question. Identify invented answers, altered source records, premature implementation or false evidence provenance.
3. **Planning and publication.** Inspect exact Planner proposals, independent Plan reviews, application identities and subsequent record revisions. The recorded run applied a proposal with ChangesRequested, then added relationships directly as governor. Judge the actual findings and changes; do not describe that proposal or those later edits as previously accepted. Explain whether any substantive planning defect remains and what correction it needs. Preserve historical deviations even when current work remedies their effects.
4. **Process graph.** Verify Idea → Goal derivation, two independent task identities derived from the Goal, their Milestone membership, and one Handoff shared through DerivedFrom links to both tasks. Idea and Goal must have no milestone ownership. Check whether the Handoff accurately describes observed results and remaining work.
5. **Incorporation.** Tie the exact Worker candidate, independent Candidate Review, fresh Reviewer oracle execution and Recorded integration to both task scopes. Current Done records must match the acknowledged integration revisions. Do not infer incorporation from a model verdict, successful process exit or result admission.
6. **Truthful boundaries.** Distinguish observations from model claims. Check that claims/integration holds are released and accounting includes the earlier attempts. Do not treat incomplete token/cost observations as complete billing or efficiency evidence. Follow-up/reopening, the defect/research/upstream example, whole-M4 acceptance and designated human acceptance remain outside this assessment.

Return the ordinary typed Review, with one verdict per assigned task. Findings must identify concrete evidence and actionable corrections. Use ChangesRequested for a demonstrated unresolved defect and Blocked when missing evidence prevents a judgment; an earlier review's verdict does not dictate yours. Accepted means the inspected deliverable and this intake-to-integration process scope satisfy the rubric, while retaining any explicitly described historical deviation. It does not grant human acceptance or complete M4. Return proposal:null; any correction requires a subsequent authorized workflow.
