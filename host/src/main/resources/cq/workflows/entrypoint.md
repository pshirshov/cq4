Run the CQ {{WORKFLOW}} workflow in this interactive harness session. The harness owns the CQ stdio host; it does not launch another Governor. If CQ tools are unavailable, report that the project's `cq configure {{HARNESS}}` integration must be installed and the harness restarted.

1. Call the CQ `session` tool with `{"Context":{}}`. Read its governing instructions, complete argument guide and project identity. Keep this context across the workflow; request it again after compaction if necessary. Context names the active workflow by ID, request and cycle and does not repeat its instructions: `{"Instructions":{}}` returns the active workflow complete, with its instruction text and operator requirements, when you no longer hold them.
2. Use the user's request and supplied scope to construct a typed `WorkflowRequest.{{VARIANT}}`. Use the project ID from Context in item IDs. Create one fresh UUID for `SessionCommand.Workflow.id`. Call `session` with `{"Workflow":{"id":{"value":"UUID"},"request":WORKFLOW_REQUEST,"operatorRequirements":"USER_REQUEST_TEXT","token":TOKEN}}`. `TOKEN` is `null` unless the invocation carries a CQ driver token: for `--start-token UUID` pass `{"Start":{"token":{"value":"UUID"}}}` and for `--resume-token UUID` pass `{"Resume":{"token":{"value":"UUID"}}}`, with the invocation's roots and phase exactly as written. Pass the token only in `token`: leave the `--start-token` or `--resume-token` flag and its UUID out of `operatorRequirements`, which the host refuses when it contains the token. A resume returns the run that is already active, so wait for its work as the governing instructions say instead of starting it again. Apart from that token, `operatorRequirements` is the user's request text verbatim, including every stated check, evidence rule, constraint or prohibition; the host delivers it to Planner and Worker children and to Plan and Candidate reviewers as their operator-requirements section. Workflow flags are not requirements: when the invocation consists only of workflow flags, as a CQ driver directive does, pass `operatorRequirements` as an empty string. Retain that exact ID/request/text for retries. Follow the returned workflow instructions. When the reply's `instructions` is `{"Unchanged":{"since":ID}}`, the text is identical to the one that the Workflow reply of activation ID carried earlier in this session: follow that text, and call `{"Instructions":{}}` only if you no longer hold it. If a required argument from step 3 is missing, ask before proceeding.
3. {{ARGUMENTS}} Preserve the user's scope. Never broaden it to get past a refusal.
4. Use the CQ domain tools directly to capture/advance work and record actual human answers. Use dispatch Select, claim a complete retained choice, then StartChoice. The host assembles child prompts and retains full results. Forward handles without reading or composing child prompts/results. Drill down only when necessary and bounded. Never edit, build, test or run checks in the operator's checkout: it is your workers' integration target, and the host preserves the operator's own in-progress work there. When a host or tooling defect blocks the workers, record a Defect with the evidence by a plain create, link each blocked item BlockedBy it, do not retry or fix it, continue unrelated eligible work and report the Defect ID at the end. A child whose result failed admission is not such a defect: retry it by selecting the same work again.
5. Surface unanswered question IDs/choices, blockers, retained result handles and remaining work. Ask genuine user choices and wait for the actual answer before dependent actions. Status and cancellation remain available before activation and after scope changes. Settle active child/check/integration/combination work before activating a different workflow. A retry of an older activation returns its receipt but does not reactivate it; Context is authoritative.

Report progress to the user normally; no final GoverningReport JSON is required. Do not run `cq run` for this interactive workflow. Host termination cancels its hierarchy; a restarted connection is a new session. Preserve a failed session's directory for `cq job upload --session DIR`. Managed children have native usage accounting; Context describes outer-session coverage and its gaps.
