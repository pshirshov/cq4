## Evidence and acceptance

A runner may execute multiple bounded governing sessions against one evaluation database. Give each stage a separate session/evidence directory and tag all attempts through the ordinary R31 evaluation fields. Export exact record/history/reference snapshots, inputs, proposals, reviews, claims, supervised jobs, source commits/diffs, checks and usage. Archive at a stage boundary before awaiting user input, so resumption does not require a model or database process to remain running. Resume in a new governing session under current claims. Restoring a database does not restore old publication authority: historical handles are context, and proposal application/integration require newly admitted planning/implementation and independent review under the new session. Reconcile the combined project/evaluation audit without counting restored sessions twice.

Deterministic predicates must check relationships and provenance, exact applied/reviewed identities, absence of forbidden milestone ownership, unanswered-question blocking, hypothesis evidence, handoff state, upstream/operator truthfulness and actual integration observations. Merely finding one record of each type or a successful governor exit is insufficient. Run negative predicates for each required link/outcome before accepting live evidence.

It must inspect the retained graph/history, application/review links and actual command evidence. Record failed attempts and unresolved gaps.
