Run the CQ {{WORKFLOW}} workflow in this interactive harness session. The harness owns the CQ stdio host; it does not launch another Governor. If CQ tools are unavailable, report that the project's `cq configure {{HARNESS}}` integration must be installed and the harness restarted.

1. Call the CQ `session` tool with `{"Context":{}}`. Read its governing instructions, complete argument guide, project identity and configured routes. Keep this context across the workflow; request it again after compaction if necessary.
2. Use the user's request and supplied scope to construct a typed `WorkflowRequest.{{VARIANT}}`. Use the project ID from Context in item IDs. Create one fresh UUID for `SessionCommand.Workflow.id`. Call `session` with `{"Workflow":{"id":{"value":"UUID"},"request":WORKFLOW_REQUEST,"operatorRequirements":"USER_REQUEST_TEXT"}}`, where `operatorRequirements` is the user's request text verbatim, including every stated check, evidence rule, constraint or prohibition; the host delivers it to Planner and Worker children as their operator-requirements section. Retain that exact ID/request/text for retries. Follow the returned workflow instructions. If required roots, phase, result or action are missing, ask before proceeding.
3. Begin accepts roots (an empty set means new intake in this CQ session). Advance requires roots and through: Explore, Plan, Work, Review or Integrate. Review requires result and mode: Plan, Candidate or Audit. Upstream requires roots and action: Prepare, Report or Recheck. Preserve the user's scope. Never broaden it to get past a refusal.
4. Use the CQ domain tools directly to capture/advance work and record actual human answers. Use dispatch Select, claim a complete retained choice, then StartChoice. The host assembles child prompts and retains full results. Forward handles without reading or composing child prompts/results. Drill down only when necessary and bounded. Never edit, build, test or run checks in the operator's checkout: it is your workers' integration target, and the host preserves the operator's own in-progress work there. When a host or tooling defect blocks the workers, record a Defect with the evidence and stop.
5. Surface unanswered question IDs/choices, blockers, retained result handles and remaining work. Ask genuine user choices and wait for the actual answer before dependent actions. Status and cancellation remain available before activation and after scope changes. Settle active child/check/integration/combination work before activating a different workflow. A retry of an older activation returns its receipt but does not reactivate it; Context is authoritative.

Report progress to the user normally; no final GoverningReport JSON is required. Do not run `cq run` for this interactive workflow. Host termination cancels its hierarchy; a restarted connection is a new session. Preserve a failed session's directory for `cq job upload --session DIR`. Managed children have native usage accounting; Context describes outer-session coverage and its gaps.
