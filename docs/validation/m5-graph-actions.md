# M5 relationship editing and historical restore

The browser uses the existing generated 0.1.0 mutation API. A relationship preview names both endpoints and their exact expected revisions. References navigate to their target, and removal has its own preview. A historical restore previews current/historical content, added/removed relationships and the current revision of each changed neighbor. The server creates new revisions atomically and preserves neighbor content. A concurrent edit rejects the frozen preview; it is never silently rebased.

Before confirmation sends a request, the browser persists its generated `ChangeInput` under the project identity. An unresolved request blocks replacement graph changes for that project. Reload exposes an explicit exact retry; it retains request identity, mutations, expected revisions and reason. Only a definitive response clears that stored request. Completion reports the original project and affected revisions without selecting a previously viewed item. Content drafts continue to use their existing independent storage.
